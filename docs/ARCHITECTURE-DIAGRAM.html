2核心机制：点击穿透（整屏透明窗口的代价与解法）

为什么窗口 = 整个工作区

上游把桌宠位置存在 whale-moe:floatX/floatY（视口坐标），拖拽逻辑也在它内部。 若窗口只有桌宠那么大，一拖就被窗口边缘裁掉，等于要接管上游的拖拽。 铺满工作区 + 默认穿透，则上游的定位/拖拽/菜单/存档全部保持原行为。

窗口创建
setIgnoreMouseEvents(true,{forward:true}) —— 默认全穿透
命中判定
elementFromPoint 命中 html/body 之外 ⇒ 压到她了（吃上游 CSS 的 pointer-events 结构）
切回接收
变化时 shell:interactive → 主进程 setIgnoreMouseEvents(false)

为什么不靠页面的 mousemove

Windows 上 forward:true 的转发并不可靠：实测把指针移到桌宠身上，页面收不到任何 mousemove（petRect.lastMouse 始终为空），于是"压到桌宠才接管"永远不成立 —— 穿透看着正常，但她永远点不动。合成移动（SetCursorPos）不行、真实鼠标有时行， 所以这个 bug 时有时无、极难复现。

主通道
主进程 80ms 轮询推 shell:cursor（确定性）
快通道
页内 mousemove 保留（能工作时更灵敏），两条都汇进 applyCursor()
兜底
blur / mouseleave 后回到穿透；有右键菜单时不抢
不许给 body 设 pointer-events:none。该属性会被子元素继承，上游弹到 body 上的菜单会一起变成不可点（shell.css）。

单价从哪来（三层分离）

模块只回答一个问题
pricing.json官方价目表（本地文件，运行时只读、不联网）
price-table.js此刻该用哪一档价：按模型 + 别名 + 峰谷取（resolveRates L84）；模型不在表里 ⇒ 回落手动配置（高峰 ×2）
pricing.js怎么乘：纯函数 costOf / isPeak / 格式化（formatTokens / formatMoney），不判断时段
usage-today.js今天一共多少：落盘、按本地日期归零、会话#turn 去重、启动回放当天历史

当前模型怎么知道：会话记录 request/header 里的 data.header.config.model （assistant/message 里没有模型名）；没读到就回落 ~/.dsh/settings.yaml 的默认模型。 所以中途换模型不用重启，设置窗口那行每 2 秒自动跟上（shell:price-info）。

为什么计时点要挪：上游 showLineNow 在开口那一刻就设 4.5 秒到期，而台词逐字打 （标点 260ms、每 5 字 130ms、其余 64ms），四十多字的余额播报光打字就 4 秒 —— 注入的钩子改成等 typingTimer 空了再计时，停留 5 秒，任意点击立刻收起。

余额查询链路（为什么要一个本地代理）

形状不兼容
官方 {is_available, balance_infos:[{currency,total_balance,…}]} ≠ 上游要的 {ok:true, balances:[{currency,totalBalance}]} ⇒ balance-proxy.js 取 Key、转字段、补 CORS 头

念那句话

5数据流 C：「打开DSH」启动决策与交接

① 探活
probeDshWeb() 只看"HTTP 有没有应答"：401 = 在跑，连接被拒才是没跑。 反过来会把"在跑"当"没跑"，平白再拉一个服务抢同一端口 —— 更糟。 open-dsh.js L135
② 在跑
只 shell.openExternal，一个进程都不动。token 每次启动都换，重启等于打断用户正在聊的会话 —— 这是硬约束，不是优化。
③ 没跑：定计划
resolveLaunchPlan() 按优先级挑路（见下表），并把 plan 摘要暴露给设置窗口与 /__shell/state L294
④ 交接起进程
生成 PowerShell 脚本 → -EncodedCommand（UTF-16LE base64）→ Start-Process -WindowStyle Hidden -PassThru， 回传 DSHLAUNCHPID=。不 spawn 到自己身上：桌宠是 GUI 进程，直接 spawn 的子进程与它共用隐藏控制台， 一个 Ctrl+C / 关控制台就整串带走（0.12.0 现场只剩一行 ^C + 0xC000013A） buildHandoffScript L392 · launchDshService L~480
⑤ 等就绪
轮询到应答（默认 60s），每轮顺手做两件事：从日志尾巴捞 token 地址、看进程还活着没（提前死就立刻报 exited，不干等超时）。 探活成功后再给最多 2 秒补 token（实测 6.5s 应答、7.4s 才写 token 行）—— 不等就会退化成打开裸地址、无 cookie 者必然 401。 waitForDshWeb L535
⑥ 回落与善后
拉起前摘掉 DSH_SHELL/DSH_SESSION_ID/DSH_WEB_URL（描述"我在哪个会话里"，对新服务是错的）， 保留 DSH_HOME；一律 --no-open（浏览器由我们开，才能回报"起没起来"）。 openDshPending 让连点两下共享同一次操作。

启动计划优先级

优先级路线什么时候用 / 注意
1用户配置的 dshCommand非空时。.bat/.cmd/.ps1/.exe 视为"启动脚本，原样跑"，否则当命令并追加 web --no-open --port
2工作空间启动脚本 Start-DSH-Web-Background.bat(.cmd)程序目录或上级目录里存在时。地址必须是 DSH 默认端口 —— 脚本不接受 --port，硬用会让"打开的地址"和"监听的端口"各说各话。日志在脚本旁边
3anode <dsh>/lib/bin.js web …从 npm 全局 shim 推出 bin.js 且 PATH 里有 node.exe；不过 cmd.exe 就少一层引号与控制台麻烦
3bcmd /c <dsh.cmd> web …只有 shim、没有 bin.js/node.exe
3cnpx --yes @deepseek-ai/dsh web …都没找到时的兜底（最慢）
环境变量大小写的坑：{...process.env} 拷成普通对象后 env.PATH 会取到 undefined —— Windows 环境变量名不分大小写，但 process.env 是大小写不敏感的特例对象，一拷就没了这个特性（这台机器上拷出来是 Path）。 后果是找 node.exe 一路失败、悄悄退化成最慢的 npx。现在统一走 envGet()。

6入口职责划分（新增功能该放哪）

右键桌宠

只放"对她做的事" + 唤起 DSH：投喂 / 戳一下 / 夸夸 / 两个小游戏 / 回到原位 / 打开DSH。

心智是"我要逗她"；「打开DSH」是同层级的"通过她做一件事"。

壳层在这里做两件修补：
① clampIntoViewport() 用实测矩形夹回视口（上游写死 180×160，实测 8 项菜单 194×292）；
② stripNonInteractionItems() 摘掉上游"打开看板娘设置"，injectOpenDshItem() 补进「打开DSH」——先摘后补，顺序反了插入位置就算错。 shell.js watchMenu L138

托盘

高频全局动作 + 快速开关：显示桌宠 / 总是置顶 / 跟随 DSH / 开机自启 / 大小 / 重置位置 / 重新加载 / 打开数据目录 / 打开日志 / 设置… / 退出。

她藏起来时唯一还能点到的入口，所以"顺手就要用"的留在这里。

与设置窗口是同一份 config 的两个入口，不会打架：所有 setter 末尾都 refreshTrayMenu()，托盘每次重建都重读 config。 不变量：新增任何改 config 的 setter，末尾必须带上 refreshTrayMenu()。

设置窗口

需要解释的配置项，按 6 类分屏。三条实现约定：
① 左侧导航由 <section data-panel> 的 <h2> 自动生成，加一屏就多一项；
② 高度由页面量好经 shell:settings-size 报上来（主进程读不到渲染进程布局）；
③ 量高度不能用 body.scrollHeight（下限是可视高度，永远缩不回去），要按"留白+标题+最高一屏+底栏"逐项相加。

⚙ 齿轮浮层 = 状态（天气 / 余额）+ 两个入口（日常养成 / 余额查询），点任一项先收起再执行（closeAnd）。

桌宠偏好走 localStorage，壳配置走 IPC —— 这个分工不能混：PET_PREFS（pet/chat/particles）与城市/Key/余额地址全写 whale-moe:*；缩放、置顶、自启、跟随、花费播报、dshUrl/dshCommand 全走 api.setConfig。

重启常驻桌宠（改完代码要让它生效）

用 WMI 创建进程是为了让父进程不是当前 shell（否则 shell 一退它可能被牵连）：

$exe = 'D:\DSWorkspace\dsh-whale-desktop\node_modules\electron\dist\electron.exe'
& taskkill /PID <旧pid> /T /F
([wmiclass]'Win32_Process').Create('"' + $exe + '" "D:\DSWorkspace\dsh-whale-desktop"', 'D:\DSWorkspace\dsh-whale-desktop')

按端口收进程而不是 taskkill /T：父进程先退出时树枚举抓不到子进程（实测漏过三个）， 于是"起来了但日志是空的"其实是上一个用例的残留服务还占着端口。

12铁律与已知限制

八条不能碰的线

  • 绝不改 vendor/whale/ —— sync 会覆盖，改行为走注入/DOM 后处理/垫片
  • 绝不重启正在跑的 DSH —— 每次启动换 token，重启打断用户会话；「打开DSH」是唤起优先
  • 不要用 PowerShell 改仓库文本文件 —— PS 5.1 按 GBK 读无 BOM UTF-8、按 ANSI 写回，中文成片变 ?（真毁过 350 行）
  • .ps1 含中文必须 UTF-8 with BOM（新脚本一律写纯 ASCII 更省事）；编辑工具会丢 BOM 并写成 LF
  • 改断言同步改 expected，否则"跑绿了"其实是少跑了
  • 探针不许有副作用：不弹浏览器、不改用户配置、不写用户账本（用 --standalone + 独立端口 + usage-today-probe.json + dry-run）
  • 不替用户决定启停：桌宠对 DSH 只做只读观察与唤起
  • 注释里别写 **/xxx —— **/ 会提前结束块注释，报 SyntaxError

已知限制（不是 bug，别当 bug 修）

  • 只铺满主显示器工作区，多屏未支持
  • 花费用量按 turn 累加，子代理的 token 也计入；账本只覆盖当前正在跟的那个会话
  • 计费不处理中国法定节假日（那几天官方按空闲价，我们会高估最多一倍）
  • 余额依赖上游 60s 刷新 + 内置代理；代理端口被占时不启动
  • 「打开DSH」不会替你重启正在跑的 DSH（设计如此）
  • 未打包：electron-builder 还没接（路线图第 2 项）
  • openSettingsWindow 还没复用 createAuxWindow，两份实现别漂移

路线图：多显示器 / 打包免安装 exe / 全局快捷键自定义 / 每屏一只 / 花费播报的节假日与主子代理区分。

13.2 两条"行数偏差"是假结论 —— 错在我的命令

初稿说 HANDOVER 的 main.js 2628 行 / shell.js 819 行"过时"。错的是我的命令，不是文档。

我的读法
(Get-Content <file>).Count → 本机得到 main.js = 2628、shell.js = 819
权威读法
按 LF 字节数（Node fs.readFileSync）与 git blob 数，两个来源一致给出 main.js = 2847、shell.js = 903；工作区是 LF（不是 CRLF），提交里的 blob 也是同一份内容
所以
HANDOVER 的 2628 / 819 本来就不对（它记的是更早版本的行数）， 而我用 Get-Content 数出来的数碰巧和它一样 —— 两边都错，我却据此宣布"文档漂移、我的图是对的"。 教训：先说清证据来源，再下结论（这正是 HANDOVER 第 11 节那句"证据优先于感觉"）。

结论：以 git show HEAD:<file> 或 Node 的 LF 计数为准。 这份框架图里的行数已按此复核过一遍；Get-Content | Measure-Object -Line 在这台机器上会少报，别用它数行。
